# 理论学习系统 V3（红色主题、活动删除与独立归档）

## 替换文件
在你现有的 GitHub 仓库 `tonguu/theory-reflection` 中覆盖 `index.html`、`style.css`、`app.js`。其他文件 (`config.js`、`report-template.docx`、`ppt-background.png`) 保留原样。

本次无需运行新的 SQL：旧版数据库中 `activities` 与 `submissions` 通过 `activity_id` 关联，外键采用 `ON DELETE CASCADE`。只使用了原有管理员读写权限。若数据库后来改动过，请先检查外键及 RLS。

## 功能说明
- 管理活动时点击“关闭当前活动”：不删除数据，只是停止征集。
- 点击“永久删除当前活动”：先显示该活动所有投稿总数，二次输入学习主题确认，活动及其关联投稿一并删除且无法恢复。**删除前建议导出报告或备份数据。**
- 每条投稿有“调整主题”，可将错归类投稿移动到其他学习活动，移动后变为待审核。目标活动如已有相同姓名年级的投稿，会提示数据库唯一约束错误。
- 管理页选择活动后只加载该 `activity_id` 对应的投稿；导出 Word 也单独按选中活动读取已审核心得。
- “导出学习 PPT”按钮和 PPT 生成代码已删除；Word 生成时仍使用 `ppt-background.png` 作为插图背景。
- 整体视觉调整为红色系。

## 对当前旧稿分类的特别提醒
原系统也已使用 `activity_id` 归档。如果同一个主题下有不同月份的内容，通常是历史投稿被提交到同一活动，而不是 Word 导出自动混合。此版提供逐条“调整主题”功能；不会按文章中的月份自动重分类，以免误判。

## 校验
- GitHub Pages 更新后用 Ctrl+F5 强制刷新；手机则关闭旧页面重新进入。
- 先用一条测试投稿验证“调整主题”，核对原活动投稿数减少、目标活动增加，Word 导出正确。
- 先测试“关闭活动”，不要直接用真实活动测试永久删除。
