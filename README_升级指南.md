# 理论学习心得管理系统 V2 — GitHub Pages 增量升级

## 文件说明

- `index.html`、`style.css`、`app.js`：替换 GitHub 仓库根目录同名文件。
- `report-template.docx`：新上传的电子与信息学院理论学习报告，保留原表格、样式；将活动信息和心得用模板变量填充。
- `ppt-background.png`：从用户上传的红色理论学习会 PPT 中提取的背景，用来生成可编辑文字的 PPT 及 Word 配图。
- `ppt-template.pptx`：用户提供的原 PPT 备份，非网站运行必需。
- `upgrade.sql`：**仅升级用**。在同一个 Supabase 项目的 SQL Editor 执行一次。原有的 activities、submissions、admin_users 保留，旧数据不清空。
- `config-example.js`：仅示例。**GitHub 原有 config.js 已填好，请保持不变，不要覆盖。**

## 操作顺序（很重要）

1. 在 Supabase 控制台打开 `SQL Editor`，完整执行 `upgrade.sql`；成功后，`activities` 表应多出 `study_month`、`notice_text`、`material_title`、`material_url`、`deadline` 等字段，`submissions` 多出 `edit_token_hash`。
2. 到 GitHub 仓库 `tonguu/theory-reflection` 的 Code 页，更新 `index.html`、`style.css`、`app.js`、`report-template.docx`，并新增 `ppt-background.png`。**原来的 config.js 保持不变**。
3. 确认 GitHub Pages 来源仍为 `main / (root)`，访问 `https://tonguu.github.io/theory-reflection/`，使用 Ctrl+F5 或手机清理网页缓存。
4. 用已有授权管理员邮箱密码登录。在管理员页面创建一场学习活动，填写月份、学习主题、截止时间，并将整段学习通知粘贴到解析框，点击“智能提取通知信息”；检查后再保存。
5. 普通成员查看学习材料并提交；第一次提交后应立即复制保存恢复码。今后在“我的历史”页面可查看、修改并重新送审。管理员审核通过后即可导出 Word / PPT 或报道初稿。

## 关于模板和图片

- Word 原始模板中的表格、标题样式和心得段落样式保留；姓名、学院、年级、正文按投稿生成。
- 使用 PPT 提取的背景生成红色风格演示页，PPT 中新增的文字为可编辑文本框，支持再次调整。
- 报告中“学习开展照片或截图”部分会插入 PPT 展示页预览图，并明确标为 PPT 展示页，**不假装是真实活动现场照片**。
- 管理员可在导出时额外选择本机的实际学习照片；照片会嵌入当次导出的 Word，但不会自动上传到服务器长期保存。以后重导需重新选择。
- 如果要把公众号文章中的完整图片/图文自动变成 PPT 页面，需要公众号正文解析服务或管理员提供原始素材；本版只从通知中提取主题、材料标题、链接、月份、截止时间，不抓取公众号文章内容。

## 权限与历史投稿

- 6 位管理员沿用原 Supabase Auth 账号和 `admin_users` 授权名单。普通成员不允许直接读取全部投稿。
- 新版每个投稿生成 64 位专属恢复码，本设备浏览器自动保存，同时可复制以跨设备恢复。后端只保存 SHA-256 哈希，只有拥有该恢复码的人能读写对应投稿。请不要把恢复码告诉其他人；它相当于修改权限。
- 原有投稿从未生成恢复码，因此**无法自动认领**。管理员可直接编辑这些旧投稿。
- 一旦普通成员修改，审核状态会恢复为“待审核”。超过截止时间不能再修改。
- `upgrade.sql` 关闭了旧的匿名投稿接口，新的投稿使用 `submit_reflection_v2`。
- 若公开访问量较大，建议后续增加人机验证/服务端限流；随机恢复码仅提供授权凭证，不等于防刷系统。

## 导出与设备

- Word 文件名固定为 `【X月理论学习】电子与信息学院理论学习报告.docx`，其中只按活动设置更改 X。
- PPT 文件名固定为 `【X月理论学习】电子与信息学院理论学习会.pptx`。
- 手机使用浏览器分享 API（支持时）显示系统分享菜单；不支持时自动回退浏览器下载。**微信内置浏览器可能仍限制下载，建议在 Safari / Chrome 中打开。**
- 报道生成基于活动信息和真实审核通过的投稿摘句，不调用 AI 模型，也不会自动编造会议日期、人数和引语，发布前必须人工审核。
- Word/PPT 客户端生成依赖公开 CDN 的 JavaScript 库，打开网页时需要能访问 CDN；GitHub Pages 不能运行 Python 后端。
